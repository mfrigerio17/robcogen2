Octave functions to test the code generated by RobCoGen, both C++ and Octave

# Introduction

Every test compares the numerical output of the RobCoGen implementation
(either C++ or Octave) with the output of the corresponding function in Roy
Featherstone's [spatial_v2](http://royfeatherstone.org/spatial/v2/)
(itself written in Octave).

The inputs for the function to be tested are randomly generated.

Every test displays the numerical results on the screen,
including the difference between the two implementations, which would be zero if
everything is correct.

Roy's code (spatial v2), the RobCoGen-erated Octave code, and obviously these
test-functions, must all be in Octave's path. I.e.:

```octave
addpath( genpath( '<your path of spatial v2>' ) );
addpath( '<your path of RobCoGen-generated Octave code>' );
addpath( '<RobCoGen root>/testing/src' );
```

RobCoGen supports testing, by generating resources in addition to the solvers
themselves:

  - an Octave function that returns the robot model as required by `spatial_v2`
  - C++ binaries that meet the requirements for testing, as detailed below

But also:

  - some master test scripts that attempt to automate the process


# Testing C++ code

In general, the Octave test-function will have this form:

`[ROY, RCG] = testcpp_xxx(ROY_MODEL, CPP_BINARY)`

where `xxx` depends on the solver (e.g. `id` for inverse dynamics, `fd_fb` for
forward dynamics for floating base robots, etc).

- `ROY_MODEL` is the robot model (a struct) in Roy's format.

- `CPP_BINARY` is a string with the full path of a C++ executable which shall use the
   RobCoGen dynamics (forward dynamics, inverse dynamics, etc., whichever you
   want to test).

- `ROY` and `RCG` are data structures with the numerical outputs, respectively
   from Roy's code and from the RobCoGen-erated code.

## Example
```octave
robot    = rcg2.init();
roymodel = rcg2.RoyModel(robot.mgc, robot.mgp, robot.mic, robot.mip);

exe = '<path to the executable>' % A string with the full path of the binary C++ program

[roy, rcg] = testcpp_jsim_fd(roymodel, exe); % Test the calculation of the JSIM for floating base robots
```

Some of the identifiers in this code snippet may be different for you,
depending on your configuration.

## Details

`CPP_BINARY` must be built beforehand. One may use the binaries built by the
RobCoGen-erated CMake file from RobCoGen-erated C++ sources, provided for
convenience.

In any case, `CPP_BINARY` shall:

  - take command line arguments for all the required inputs, which depend on the
    specific function. The arguments are typically the coordinates
    of the joint status vector, joint velocity vector, etc., in the "usual"
    order.  
    For example, to test the inverse dynamics of a 5-dof fixed-base robot, the
    binary shall take 15 arguments, for the 5 coordinates of the joint position,
    velocity and acceleration vectors.  
    See the documentation or the code of each test-function for specific info.

  - take a last command line argument with the full path of a text file, which
    contains the external forces acting on each link (optional). One line for
    each force (i.e. each link), six values for each line (the coordinates of
    the spatial force acting on the link, in link coordinates).

  - print the resulting output to stdout. Octave takes this output and converts
    it into a local variable to compare it with Roy's output.
    Also the actual output depends on the specific dynamics
    function being tested, obviously. For example, an executable running the
    fixed base forward dynamics of a robot will have to print the joint
    acceleration vector.  
    In general, the results are expected to be printed one after the
    other, as column vectors, one coordinate per line.

# Testing Octave code

In general, the Octave test-function will have this form:

`[ROY, RCG] = test_xxx(ROY_MODEL, ROBCOGEN_MODEL)`

- `ROY_MODEL` is the robot model (a data structure) in Roy's format. Same as the
   C++ test.

- `ROBCOGEN_MODEL` is a data structure with some fields initialized with the
   robot-specific functions generated by RobCoGen.

- `ROY` and `RCG` are data structures with the numerical outputs, respectively
   from Roy's code and from the RobCoGen-erated code.

## Example
In Octave's prompt:

```octave
rcgmodel = rcg2.init();
roymodel = rcg2.RoyModel(rcgmodel.mgc, rcgmodel.mgp, rcgmodel.mic, rcgmodel.mip);

[roy, rcg] = test_id(roymodel, rcgmodel);
```


# Caveats
**! WARNING !**

RobCoGen code requires the external forces to be supplied in body coordinates.
Roy's code unfortunately expects forces in world coordinates (and it converts
them to body coordinates internally!).

I haven't written a conversion as it is particularly boring.

Therefore the tests as they are now will never succeed, unless you modify
slightly Roy's implementation of the algorithms to expect external forces
already in body coordinates (or you set all forces to be zero). The change is
pretty easy, and it could look like this (example from the floating base
forward dynamics):

```octave
% ...

% Comment the next line out; that's the original
% pA(6:end) = apply_external_forces(prnt, Xup(6:end), pA(6:end), f_ext(6:end));

for i = 6:model.NB
  pA{i} = pA{i} - f_ext{i}; % everything here is in body coordinates
end

% ...
```
